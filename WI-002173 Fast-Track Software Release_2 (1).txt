1 Purpose
The purpose of this Work Instruction is to establish a process for a Fast-Track Software Release in
special cases.
2 Scope
This work instruction applies to all software products with the following predefined changes during
development:
o Internationalization (add or changes in language files)
o Software Labeling (change the labeling of the software from IUO to IVD)
o Cybersecurity (minor updates of 3rd party components)
This work instruction describes details necessary to comply with regulations and requirements, which
are intended to result in validated products for the customer.
This work instruction applies to all software R&D and production activities (including firmware) at Bruker
Hain Lifescience GmbH (hereinafter referred to as Bruker), and covers Tier I, II, and III development
projects.
3 Description
The goal is to ensure, that all need steps in the development lifecycle are performed and all unnecessary
steps are skipped. These steps are performed without crossing the phase boundaries of the
development process.
3.1 Fast Track Release Situations
3.1.1 Change in Internationalization
Software is released with the capability to internationalize the software GUI. This means that new
languages may be introduced, or existing languages may receive updates. Both of these actions are
performed by modification of special language files.
The first software release usually includes German and English as initial languages. Afterwards
additional language could be added.
These changes happen without modification of the main source code (only language files are modified)
and only require an update of the software installer. To identify changes in language files, the last
position in the version number of the Software will be increased. 3.1.2 Cybersecurity
During the release process cybersecurity issues in 3rd party libraries can arise, which need immediately
actions prior to the software release.
If these changes are minor changes to the software product, e.g., updates of 3rd party components
without breaking any compatibility with the existing code, the Fast-Track Release can be applied.
These changes are no changes in the source code (except changes in the last position in the version
number) and only in the installer of the Software.

3.1.3 Software Labeling
After IVD validation of the software, the labeling of the software must be changed from IUO to IVD prior
to the manufacturing release.
These changes only have a small impact, because there are only small changes of the labeling of the software and a change in the installer of the software.
3.2 Process steps that can be skipped
The following steps in the software and product development lifecycle can be skipped during a Fast-
Track Release. 3.2.1 Phase 2 Tasks• Software Verification• Phase transition
3.2.2 Phase 3A Task• Risk Analysis• IFU Creation
• Definition of PMS• Software Translation• Software training• Phase transition
3.2.3 Phase 3B Task• Software validation• Usability testing• Clinical Study• Registration• Phase transition
If one or more of the steps was not performed during the first release round, it must be performed during the Fast-Track Release. After reaching the process stage that initiated the Fast-Track Release, the
development will continue the original process.
All deliverables of the D&DP must be completed or updated.
3.3 Mandatory Process Steps
The following Steps in the Software and Product development lifecycle cannot be skipped during Fast-
Track Release. Additionally, it must be considered if changes to the risk management file are required.
3.3.1 Phase 2 Task• Update Software Verification and Validation Master Plan
o Perform Installation Test
o Perform Smoke Test
• Update Software Release Notes• Software Finalization Release• Update Cybersecurity Master Record• Update SBOM
